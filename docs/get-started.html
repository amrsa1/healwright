From npm install to a test that heals its own broken selectors. You need Playwright 1.62 or newer, and either an API key for a cloud model or Ollama running on your machine.

1Install

Add healwright to the project that holds your Playwright tests.

2Pick a provider

Healing stays off until SELF_HEAL=1, so your suite runs exactly as before until you turn it on. healwright reads environment variables: set them in CI, or load a .env file with import 'dotenv/config' at the top of playwright.config.ts.

Behind a gateway? AI_BASE_URL points any built-in provider at Azure, OpenRouter, vLLM or LiteLLM. For a model healwright has no client for, pass your own with the aiProvider option.

3Add the fixture

Wrap the page fixture once. Every test that imports test from this file gets page.heal; everything else on page works as usual.

4Write a test

Each page.heal action takes a selector and a description. The selector runs first; the description is what the model looks for when the selector stops matching. Leave the selector empty and the description is enough.

Describe elements the way you'd point them out to a colleague: "Place order button", not "button". The model has only your words and the page to go on.

5Run it

While your selectors match, nothing changes and tests run at full speed. When one breaks, the heal shows up in the output. The next run reads the fix from the cache and doesn't call the model.

6Keep it honest

A heal that lands on the wrong element still passes. These three settings decide how far the model is trusted and keep every heal visible. You can try them on the home page.

minConfidence
Fail the action instead of guessing when the model's confidence is below this score (0 to 1).
mode: 'warn'
Report what would have healed and keep the original failure. Use it in CI to see how far your selectors have drifted.
getHealSummary()
Count every heal in the run, so global teardown can fail the build and list the selectors to fix.

Running Playwright in UI or watch mode? Call resetHealSummary() from globalSetup so each run starts at zero.

7Cache and logs

healwright keeps three files in .self-heal/.

File What's in it In git?
healed_locators.json Every heal that worked, by action, page path and description. Commit it to share heals with your team and CI.
heal_events.jsonl One line per heal attempt, with the model's reason, confidence and token count. Ignore
heal_summary.jsonl The outcomes getHealSummary() reads at the end of a run. Ignore

Reference

Methods on page.heal

Every action takes a selector or Locator (or '' for description only) and a description.

Method What it does
click(target, desc, { force? })Click. force: true clicks controls that only appear on hover.
dblclick(target, desc)Double-click.
fill(target, desc, value)Type into an input or textarea.
selectOption(target, desc, value)Choose an option in a dropdown.
check(target, desc)Check a checkbox or radio.
uncheck(target, desc)Uncheck a checkbox.
hover(target, desc)Hover over an element.
focus(target, desc)Focus an element.
locator(selector, desc)A chainable locator with the same actions: .locator('.save', 'Save button').click().
getLocator(selector, desc)Returns a real Playwright Locator, for expect(), .nth(), .filter() and the rest.
